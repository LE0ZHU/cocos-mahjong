# 麻将（Cocos Creator 3D 版）

单人对局 · 三家 AI 的中国麻将。原生 + Web 双端，界面按桌面第一视角做了透视与自适应。

引擎：**Cocos Creator 3.8.8** ｜ 语言：TypeScript（`strict: false`，target ES2015）

---

## 运行

1. 用 Cocos Creator 3.8.8 打开本目录
2. 打开场景 `assets/game.scene`，点预览（浏览器）或构建到 Android/iOS
3. 场景里只有一个 `Main` 脚本挂在 Canvas 下，`GameManager` 由它在运行时创建

## 操作

| 操作 | 效果 |
|---|---|
| 点击手牌 | 选中（突出显示） |
| 再次点击同一张 | 打出 |
| 按住手牌往上拖，出手牌区后松手 | 打出（牌跟着手指走） |
| 点击其他区域 | 取消选中 |
| 主菜单「玩法说明」 | 番型表 / 计分口径 / 操作说明 —— 新玩家上手先看这一页（可上下拖动） |
| 左上角齿轮按钮 | 打开设置弹窗：声音设置 / 重新开始（保留累计分与连庄）/ 返回主页面（清零） |
| 听牌时手牌左侧出现「听牌」按钮 | 宣告听牌（加 1 番） |
| 提示按钮 | 需要做决定时亮起，给出与 AI 同源的建议打法 |
| 齿轮右侧的比分条（常驻） | 随时看到四家累计分，不用等一局结束 |
| 手牌右侧的听牌芯片（常驻） | 听牌后一直显示「听 3/6萬 · 余 4 张」，不用点提示 |
| 主菜单底部的「生涯 …」 | 跨会话战绩：总局数 / 胡牌次数 / 最高番 / 最长连庄 |

出牌没有按钮：轮到自己自动摸牌，点两下手牌就出。

## 玩法

**流程**：发牌 → 摸/出 → 副露（吃/碰/杠/续杠）→ 胡牌或流局

**胡牌方式**：自摸必可；开启「吃胡」后也可胡别人打出的牌；补杠时可被抢杠。

**一炮多响**：同一张牌可以被多家同时胡。玩家逐个决定是否参与，AI 自动参与。

**听牌（立直）**：手牌听牌后可点「听牌」亮明给对手看，加 1 番。宣告后本局不能再吃/碰/杠，且出牌必须保持听牌。AI 听牌后自动亮明，并改为只打保持听牌的牌。

### 番型与计分

底分 1 分，**每 1 番翻一倍**，8 番封顶（= 256 分）。

| 类别 | 番型 |
|---|---|
| 牌型 | 十三幺 6 ｜ 七对 2 ｜ 对对胡 2 ｜ 平胡 0 |
| 花色 | 清一色 4 ｜ 混一色 2 ｜ 字一色 2 |
| 状态 | 自摸 1 ｜ 门清 1 ｜ 立直 1 ｜ 杠上开花 1 ｜ 抢杠胡 1 ｜ 海底捞月 1 |
| 连庄 | 连续第 N 次胡加 (N−1) 番，最多 3 番 |

**支付**：自摸 = 三家各付一份；点炮 / 抢杠 = 付分方一次付清；一炮多响时付分方需赔付给每家赢家。
**连庄与累计分跨局保留**，只有返回主页面才清零（单局内不可能有"第二次连庄"）。
每局结算后它们还会**写进本地存储**，所以切后台被系统回收、或应用被杀掉之后重开，
比分能接着上一局继续（主动返回主页面才算这一串对局打完，那时才清零）。

### 跨会话战绩

| 数据 | 存多久 | 在哪看 |
|---|---|---|
| 累计分 / 连庄（当前这一串对局） | 返回主页面为止 | 牌桌左上角比分条 |
| 总局数 / 胡牌次数 / 最高番 / 最长连庄（生涯） | 长期保留 | 主菜单底部一行 + 结算面板底部一行 |

生涯统计是**玩家口径**（只记"你"的成绩），流局也算一局但不涨胡牌次数与最高番。

### AI 拟人化

三家 AI 各有名字与口头禅：上家**老陈**（沉稳）、左家**小雨**（活泼）、右家**阿虎**（直爽）。

- 碰 / 杠：说话那家的手牌上冒一个短气泡（带名字），停留约 1.6 秒
- 胡牌 / 点炮：整句显示在结算面板里 —— 那时牌桌已被结算遮罩盖住，气泡是看不见的
- 吃牌不给台词（频率高得多，每次都说话就成了噪音；与震动同一口径）

名字必须是**两个汉字**：牌桌上显示座位名的地方（比分条四枚芯片、"xx·听"标记、
结算名牌）都是按"上家 / 左家 / 右家"这两个字的宽度排的，换名字不能改版式。

### 设置项（主页面 → 设置规则，下一局生效）

| 选项 | 说明 |
|---|---|
| 吃牌 | 只能吃上家打出的牌 |
| 续杠 | 碰过之后再摸到同一张，可补成杠 |
| 吃胡 | 听牌时别人打出所听的牌，可选择胡 |
| 抢杠胡 | 别人补杠时可以抢那张牌胡（优先于补杠） |
| 一炮多响 | 多家同时听同一张牌时可一起胡 |
| 听牌宣言 | 亮明听牌加 1 番，之后不可吃碰杠 |
| AI 思考速度 | 快 / 常规 / 慢（出牌间隔 0.22 / 0.5 / 0.9 秒） |

## 目录结构

```
assets/
  game.scene              唯一场景（Canvas + Camera + Main）
  resources/              运行时 resources.load 的资源
    menu_bg.jpg           主菜单背景（JPEG，约 440KB）
    tiles/                34 种牌面图（圆角 PNG，由 tools/make-tile-faces.py 加工）
    audio/                bgm + 牌名报牌 / 动作音效
  scripts/
    Main.ts               主场景脚本：牌桌 UI、交互、动画、布局（3015 行）
    core/                 纯逻辑，不依赖 cc 引擎 —— 可脱离引擎单测
      TileDefine.ts       花色/点数/配色常量
      Tile.ts             单张牌
      Wall.ts             136 张牌墙 + 洗牌 + 摸牌
      Meld.ts / MeldDetector.ts   副露数据与吃碰杠检测
      HuChecker.ts        胡牌判定 + 牌型拆解（analyze）+ 听牌枚举
      HuScore.ts          番型判定与计分 + 结算数据结构
      Shanten.ts          向听数与进张（与 HuChecker 同一套判定）
      AIDefense.ts        防守评估：他家和牌危险度
    game/                 规则与 AI
      Player.ts           一家的手牌/副露/弃牌/听牌状态（纯逻辑）
      AIBrain.ts          AI 出牌与副露决策（纯逻辑，暴露评分明细）
      HintAdvisor.ts      玩家提示：复用 AI 的评分结果
      AIPersona.ts        三家 AI 的名字与碰/杠/胡/点炮台词（纯数据）
      CareerStats.ts      生涯统计 + 比分快照：累加口径与存档编解码（纯逻辑）
      CareerStore.ts      战绩落盘（依赖 cc 的 sys；与 GameRules 同一条分层例外）
      GameRules.ts        规则开关（依赖 cc 的 sys 做 localStorage 持久化）
    managers/
      GameManager.ts      全局状态机：回合调度、胡牌判定、计分结算、战绩落盘（1717 行）
    ui/
      UIFactory.ts        控件工厂（牌节点/按钮/文字/牌身）
      TileView.ts         牌的交互组件（点击选中、拖拽出牌）
      TileImage.ts        牌面图预加载
      Anim.ts             补间动画封装
      MenuUI.ts           主页面 / 规则设置页 / 玩法说明页（可滚动；番型表来自 HuScore.FAN_DEFS）
      SettlementPanel.ts  结算面板（番型 + 四家得失分 + 四家手牌）
      HintPanel.ts        「提示」浮层（建议打法说明）
      SettingsPanel.ts    对局内设置弹窗（声音 / 重新开始 / 返回）
    feedback/Haptics.ts   触觉反馈（震动）：碰/杠一下、胡牌重一点
    audio/Sound.ts        音效与 BGM
tools/                    校验脚本（ai-test）、预览出图、素材加工、构建排查
settings/                 Cocos 项目设置
```

**架构约定**：`core/` 全部与 `game/` 的 `Player`/`AIBrain`/`HintAdvisor`/`AIPersona`/
`CareerStats` 不 import `cc`，因此可以用 tsc 编译后用 node 直接跑单测（见 `AGENTS.md`）。
例外只有两个，都只是要用引擎的 `sys` 读写 localStorage：`GameRules.ts`（规则开关）与
`CareerStore.ts`（战绩落盘）。

## 技术要点

- **自适应**：内容按宽度铺满（`_gameRoot.scale = 设计宽 / 1680`），纵向贴可见区边界，形成贴近桌面的第一视角；转屏自动重排
- **菜单内容页（设置规则 / 玩法说明）**：字号按「读」的标准给足（标题 36 / 说明 26 / 正文 28），
  内容因此高于一屏 → 走共用的滚动视口 + 右侧滚动指示条，并铺一层整页深色阅读底板压掉背景干扰
  （`MenuUI._createScrollPage` / `_addPageDim`，见 AGENTS.md 硬约束 6h）
- **原生兼容**：原生（JSB）平台在 `onLoad` 阶段画的 `Graphics` 不上屏，所有静态图形延后一帧绘制，页面重新显示时用 `repaintButtons()` 补画按钮底框
- **菜单切页过渡**：主页面 / 设置规则 / 玩法说明三页切换是淡出 0.12s → 淡入 0.16s，
  只动 `UIOpacity`（布局不参与），并用递增的序列号作废过期回调 —— 连点两次不会把刚淡入的页误隐藏
- **震动反馈**：碰/杠震 30ms、胡牌震 60ms（流局不震）。原生走引擎 `Device.vibrate`（单位是**秒**），
  Web 走 `navigator.vibrate`（单位是**毫秒**），取不到能力就静默跳过。
  Android 必须在清单里声明 `android.permission.VIBRATE` 才会真的震（引擎吞掉了权限异常），
  快迭代打包时由 `tools/patch_manifest_vibrate.py` 注入二进制 AXML
- **牌面**：素材图 1:1 铺满整张牌（圆角直接裁在图片上，`tools/make-tile-faces.py` 加工）；
  有图时程序化牌身整体隐藏；加载失败时退化为矢量绘制
- **番型表唯一真源**：`HuScore.FAN_DEFS`（名称 / 番数 / 说明）既供 `computeHu` 判定、又供
  「玩法说明」页渲染 —— 说明里写的番数就是判定用的番数，不会各写一份
- **提示与 AI 同源**：提示读的就是 AI 的评分结果（`HintAdvisor` ↔ `AIBrain`），不存在两套口径；
  手牌右侧常驻的听牌详情（`GameManager.onTenpaiInfo`）同样出自这一份算法，剩余张数
  用的是「实际张数」口径（Σ(4 − 可见张数)）
- **战绩持久化分层**：`CareerStats.ts` 只管"怎么算 / 怎么编解码"（纯函数，可单测），
  `CareerStore.ts` 只管"存到哪儿"。原生平台的 `sys.localStorage` 是**异步**就绪的，
  所以存档区分"存储就绪"与"有数据"：没就绪时只读不写，否则会用内存里的空战绩把真存档冲掉
- **AI 拟人化只作用于表现层**：名字与台词不参与任何决策计算，AI 强度恒为满能力档
